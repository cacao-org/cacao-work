# Toy-model study

A known-truth, modal, linear model of the two-stage loop, used to understand why the shipped
calibration is biased and to choose and stress an estimator before touching the simulator.
The toy shows mechanisms and ranks estimators. Its magnitudes are not those of the real system;
what was later confirmed on simulator telemetry is listed in `../README.md`.

## Read in this order

1. `REPORT.md`: the study of 2026-11-19. What the shipped algorithm does, why every regression
   of `B` on `(A, D)` is a blend in closed loop, the options compared, and the recommended
   passive estimator (its section 5.4). Generated by `code/build_report.py`; do not edit it by
   hand.
2. `notes/why_differences.md`: why the estimator works on first differences.
3. `notes/two_step_calibration.md`: two-step and low-gain schemes, and why they were dropped.
4. `notes/loop_frequencies.md`: other frame rates and clock offsets; the window rule.

## Running

```bash
cd algo/calib2wfs1dm/toy/code
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
python3 selftest.py                    # a few seconds; must print SELFTEST PASSED
python3 freq_scan5.py 20 20            # window length in s, worker processes; 7 minutes
python3 bench.py 16 && python3 theory1.py sig_nA=0.002 sig_nB=0.002 c_hi=0.6 \
    && python3 extra.py && python3 stage3.py && python3 iv_variants.py && python3 iv_lowfs.py
python3 figs.py .. --all && python3 build_report.py ..
```

- Set the three thread variables first. Most scripts start 20 worker processes; with a
  multi-threaded BLAS they oversubscribe the machine and take ten times longer.
- Run scripts as files. Multiprocessing fails when the script comes from standard input.
- The scripts need numpy; `figs.py` needs matplotlib. On the original machine the project
  interpreter (`$PYTHON_BIN`) had no matplotlib and `/usr/bin/python3` was used.
- `theory_*.npz` and `cond_*.npz` are not in git. `theory1.py` and `extra.py` write them;
  `figs.py` and `build_report.py` need them.
- `build_report.py` wraps the text at 100 characters; `--no-wrap` gives one paragraph per line.

## State of the scripts

The nine scripts of the first study (`bench.py`, `estimators.py`, `extra.py`, `figs.py`,
`iv_debug.py`, `iv_lowfs.py`, `iv_variants.py`, `stage3.py`, `theory1.py`) had lines over 100
characters. They were re-wrapped when this directory was created; their syntax trees are
identical to the versions that produced the results. `build_report.py` was changed more: it
now wraps the text, uses narrower tables and adds a note on later results. The numbers in
`REPORT.md` are unchanged.
